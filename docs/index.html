What it is

skillstate-proxy sits in front of OpenAI, Anthropic, Venice, OpenRouter, vLLM, Ollama, Gonka, or any OpenAI-compatible upstream. Each request is rewritten to spec plus current state plus latest observation. The model returns a state_patch plus an action. The proxy merges the patch, discards reasoning, and never re-sends the full transcript.

Why it saves money

Append-only transcripts grow linearly. SKILL.state stays about 1,500 tokens per step. A measured 50-step run on Venice (qwen3-5-9b, 2026-08-30) used 75,606 prompt tokens vs 274,540 baseline: 72.5 percent less, 0.0097 USD vs 0.0292 USD.

What it includes

  • Drop-in proxy — point base_url at it; OpenAI and Anthropic clients work.
  • Streaming — SSE passthrough; state updates server-side.
  • Anthropic translation — /v1/messages to OpenAI format and back.
  • Failover — multi-upstream routing with circuit breaker and rate limiter.
  • Session persistence — state on disk, survives restarts.
  • Cost tracking — JSONL ledger, 24h summaries, USD and GNK.
  • Rollback-retry — retries when the model misses structured output.
  • Schema enforcement — drops out-of-schema keys so state stays small.

Install

The CLI binary is skillstate. Full install steps are in the README on GitHub.

Start with SKILLSTATE_UPSTREAM set to an OpenAI-compatible base URL and SKILLSTATE_API_KEY set to YOUR_UPSTREAM_API_KEY (placeholder). Default listen port is 8789 on 127.0.0.1. CLI flags: --port, --verbose, --config, --help.

Point an OpenAI client base_url at http://127.0.0.1:8789/v1. Responses include x-skillstate-session, x-skillstate-step, and x-skillstate-cost-usd. Inspect GET /state, GET /cost, GET /health.

Config sketch

Environment: SKILLSTATE_UPSTREAM, SKILLSTATE_API_KEY, SKILLSTATE_PORT (default 8789), SKILLSTATE_SCHEMA, SKILLSTATE_INITIAL_STATE, SKILLSTATE_CONFIG, SKILLSTATE_VERBOSE.

Or a skillstate.json file. Keys shown are placeholders, not real credentials.

{
  "listenPort": 8789,
  "upstreams": [
    { "name": "openai", "url": "https://api.openai.com/v1", "apiKey": "YOUR_UPSTREAM_API_KEY", "priority": 0 },
    { "name": "venice", "url": "https://api.venice.ai/api/v1", "apiKey": "YOUR_SECOND_UPSTREAM_API_KEY", "priority": 1 }
  ],
  "schema": ["step", "notes", "flags"],
  "initialState": { "step": 0, "notes": [], "flags": [] },
  "maxRetries": 2,
  "cors": true
}

Priority: CLI flags, then environment, then config file, then defaults.

When not to use it

From the paper: no fixed schema in advance; deferred-relevance observations; tasks where the trajectory itself is the output (audit, provenance). Single-agent only unless you add conflict resolution for concurrent writes.
