What it is

skillstate-proxy sits in front of OpenAI, Anthropic, Venice, OpenRouter, vLLM, Ollama, Gonka, or any OpenAI-compatible upstream. Each request is rewritten to spec plus current state plus latest observation. The model returns a state_patch plus an action. The proxy merges the patch, discards reasoning, and never re-sends the full transcript.

client ──► skillstate-proxy :8789 ──► OpenAI · Anthropic · OpenRouter · Gonka · Ollama
               │
               ├─ Σ JSON on disk per session
               ├─ rewrite to (P, Σ, O)
               └─ merge ΔΣ, drop reasoning

Why it saves money

Append-only transcripts grow linearly. SKILL.state stays about 1,500 tokens per step. A measured 50-step run on Venice (qwen3-5-9b, 2026-08-30) used 75,606 prompt tokens vs 274,540 baseline: 72.5% less, $0.0097 vs $0.0292.

What it includes

  • Drop-in proxy — point base_url at it; OpenAI and Anthropic SDKs work.
  • Tool calls — tools / tool_calls pass through; tool results become the latest observation.
  • Streaming — SSE passthrough; state updates server-side.
  • Anthropic translation — /v1/messages to OpenAI format and back.
  • Failover — multi-upstream routing with circuit breaker and rate limiter.
  • Session persistence — state on disk, survives restarts.
  • Cost tracking — JSONL ledger, 24h summaries, USD and GNK.
  • Rollback-retry — retries when the model misses structured output.
  • Schema enforcement — drops out-of-schema keys so state stays small.

vs Headroom

skillstate-proxy bounds chat history. Headroom compresses tool JSON / logs. Optional stack: agent → skillstate :8789 → headroom :8788 (--backend anyllm --mode token --no-ccr) → MiniMax or OpenBroker. Headroom is a separate CLI, not a NosytLabs repo. Hermes' provider name headroom on this machine is currently a Gonka alias, not the Headroom binary.

Install

Binary is skillstate. Default listen: 127.0.0.1:8789.

git clone https://github.com/NosytLabs/skillstate-proxy.git
cd skillstate-proxy
npm install && npm run build

cp skillstate.json.example skillstate.json   # fill YOUR keys, file is gitignored

SKILLSTATE_UPSTREAM=https://api.openai.com/v1 \
SKILLSTATE_API_KEY=YOUR_UPSTREAM_API_KEY \
npm start

Point any OpenAI client at http://127.0.0.1:8789/v1. Responses include x-skillstate-session, x-skillstate-step, x-skillstate-cost-usd.

from openai import OpenAI
c = OpenAI(base_url="http://127.0.0.1:8789/v1", api_key="ignored")
r = c.chat.completions.create(
    model="gpt-4o",
    messages=[{"role":"system","content":"TASK: track state"},
              {"role":"user","content":"go"}],
)

HTTP API

Binds 127.0.0.1 only. Inspect routes also exist as /v1/health, /v1/state, /v1/cost.

MethodPathWhat it does
POST/v1/chat/completionsOpenAI chat; rewrite to (P, Σ, O)
POST/v1/messagesAnthropic Messages; translated
GET/v1/modelsProxied to the first upstream
GET/healthok plus per-upstream circuit state
GET/stateSession ids; ?session= returns step + state
DELETE/state?session=Reset that session (204)
GET/costSpend summary last 24h

Config

Copy skillstate.json.example → skillstate.json (gitignored). Never commit real keys. See SECURITY.md.

Env: SKILLSTATE_UPSTREAM, SKILLSTATE_API_KEY, SKILLSTATE_PORT (8789), SKILLSTATE_SCHEMA, SKILLSTATE_INITIAL_STATE, SKILLSTATE_CONFIG, SKILLSTATE_VERBOSE.

Priority: CLI flags → environment → config file → defaults.

When not to use it

From the paper: no fixed schema in advance; deferred-relevance observations; tasks where the trajectory itself is the output (audit, provenance). Single-agent only unless you add conflict resolution for concurrent writes.
